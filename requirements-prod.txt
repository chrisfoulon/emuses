# Production install set = the main lockfile, plus the few server-only packages.
#
# This file is deliberately NOT a pip-compile artifact any more, and `pip-compile
# requirements-prod.in` must not be run to regenerate it. It is six lines and an
# `-r` on purpose.
#
# WHY. It used to be a full 152-pin compiled lockfile, and it silently rotted: it
# was last compiled at f499567 and never recompiled as requirements.in grew. By
# 2026-09-05 it was missing 46 packages that requirements.txt had -- including the
# whole authentication stack (fastapi-users, pwdlib, bcrypt, argon2-cffi, pyjwt),
# all three cloud storage backends (boto3, azure-storage-blob,
# google-cloud-storage), hvac for Vault, redis and pymemcache for caching, and
# structlog. The image could not have started the multi-user service.
#
# It had also drifted on the five packages that decide the science: it pinned
# scipy 1.12.0, scikit-learn 1.7.1, joblib 1.5.1, numba 0.61.2 and llvmlite 0.44.0
# while requirements.txt pinned 1.17.1 / 1.7.2 / 1.5.2 / 0.62.1 / 0.45.1. numba
# and llvmlite are the compiled-kernel path whose codegen target is exactly what
# makes UMAP embeddings differ between machines (see
# tests/regression/test_numerical_regression.py). An image built from that file
# would have run the pipeline on a stack no baseline has ever validated.
#
# Nobody noticed because nothing ever installed it: the Docker build is the only
# consumer, and it had never once succeeded.
#
# Deriving prod from requirements.txt with `-r` means the two cannot diverge
# again. Add a line here only for something the *server* needs and the library
# does not.
